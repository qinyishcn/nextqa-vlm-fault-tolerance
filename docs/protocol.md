# NExT-QA 视频依赖与视觉特征容错：评测约定

此文件先于正式推理结果建立。模型系列待用户确认：用户给出的名称是
LLaVA-NeXT-Video，链接介绍的是 LLaVA-Video；不将两者当成同一 checkpoint。
当前准备规模为预先固定的60视频、495题（目标约500题）。如改为完整验证集，
另建清单与结果目录，不将两个分母混合；现有结果始终标明实际规模。

## 数据与随机基线

- 使用官方 NExT-QA 验证集，4996题、570视频、每题五个选项。
- 官方源码提交：2432e9724f88ed9f40010e2989f104570a91de4e。
- val.csv SHA-256：43198bdef8436b8d64a9b75d846b0987c10cbf94ebf4be325c4a4e54634d66b8。
- 标准标签为0至4，展示为A至E；题目、选项、标签和问题类型均保持原始含义。
- 标签、问题ID、文件名不进入模型提示词。只用验证集，模型加载不训练或调参。
- 随机选项的理论期望为20%。另保存固定种子的实际随机预测及答案位置频数。
- 是否接近随机是待检验的问题，不预设纯文本、全零或错视频必然达到20%。

若使用子集，先按视频包含的最稀有问题类型分层，固定随机种子抽视频，
保留所选视频的全部问题。根据题数选择最接近目标的分组规模，选择过程不读取
模型答案或答题表现。报告实际题数、每类型构成和源验证集构成，结果只代表该子集。

## 对照的意义

1. 纯文本：无视觉输入或视觉占位 token，仅同样的问题与五个选项。
2. 正常视觉：单帧、原生连续多帧、覆盖全视频的等间隔多帧。
3. 重复单帧：在同样的视觉 token 数下重复一帧，区分帧数和新增信息。
4. 乱序与倒序：保留同一组帧，检测对时间顺序的依赖。
5. 错配视频：固定无自配映射，给另一视频的视觉输入，保持题目和选项不变。
6. 全零视觉特征：保留视觉布局，但将切分边界上的传输特征全部置零；
   这是100%特征擦除，与纯文本、黑色图像或错配视频分别报告。
7. 分包擦除：在视觉编码/投影后的中间特征上分包，按缺包位置置零。
   保留0%和100%，记录随机种子、实际损伤比例和输入哈希，不强制准确率单调。

连续窗口与覆盖全视频是不同时间范围，匹配帧数后分别比较，不能把连续4帧的
结果解释为完整视频理解。NExT-QA 不采用 StreamingBench 的提问时刻定义；
连续窗口位置必须预先固定，并保存原生帧索引、FPS及实际时间跨度。

## 计分与核验

- 各条件使用固定题目分母。缺失或无法解析成单个A–E的答案计错，原始输出保留。
- 报告整体、因果C/时间T/描述D及细分类准确率与逐题配对变化。
- 以视频为单位进行配对bootstrap，避免把同一视频的问题当成独立样本。
- 对照随机的差异给出区间；“未发现显著差异”不等于等效。
  等效容差预设为±5个百分点，只有相应等效检验区间落入容差才称接近随机。
- 有视觉相对纯文本的增益、对时间顺序的敏感度与丢包容错分别报告。
- 在正式批次前核对完整模型和切分输入无损情况下的输出一致性；
  核对重新编码特征、损伤位置、实际传入语言模型的特征字节哈希。
- GPU精度、量化、版本与硬件在报告中说明，不冒充官方全精度成绩。
- LLaVA-Video 的公布训练混合包括 NExT-QA；如选该系列，明确这一事实，
  不把验证集表现称为未见过该数据集的零样本泛化。

## 与前次 Testbed 的关系

先完成模型和数据集依赖的离线成对对照，再沿用原版Testbed的local server、RTC、
网卡netem、profile、抓包和日志路径适配新模型。离线擦除和真实RTC网络结果分开，
不把离线随机置零称为网络实测。沿用原版网络负载预算时核对实际IP包长不超过1500，
不能将配置随机丢包率当作接收特征缺失率。按提问点传输特征和持续FPS流量分别说明。
